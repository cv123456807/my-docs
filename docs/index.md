## 这个网站想说明什么

写文档本身不难，难的是**让文档一直在正确的位置、以正确的形态存在**。过去常见的做法是把导出的 HTML 压缩包传到服务器，或者手动把生成结果提交到另一个分支，时间一长就会出现"源码改了、网站没更新""产物和源码对不上"的情况。

这次实践把这件事交给机器：源码放在 `docs/`，构建配置放在 `mkdocs.yml`，只要向 `main` 分支推送与文档相关的改动，GitHub Actions 就会在干净的环境里安装依赖、执行构建、把产物发布到 Pages。人只负责写 Markdown，其余步骤可重复、可追溯。
