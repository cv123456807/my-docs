# API 参考

以下接口仅用于文档展示，不提供真实服务。这一页的目的不是描述一个真实后端，而是练习"用结构化文字把接口讲清楚"。

## 查询文档列表

- 请求方法：GET
- 请求路径：`/api/docs`
- 功能：返回文档条目列表。

### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `page` | query | integer | 否 | 页码，默认 1 |
| `size` | query | integer | 否 | 每页条数，默认 20，最大 100 |
| `keyword` | query | string | 否 | 按标题模糊匹配 |

### 返回示例

```json
{
  "total": 2,
  "page": 1,
  "size": 20,
  "items": [
    { "id": 1, "title": "使用指南", "updated": "2026-11-22" },
    { "id": 2, "title": "关于本项目", "updated": "2026-11-22" }
  ]
}
```

### 状态码

| 状态码 | 含义 | 处理建议 |
| --- | --- | --- |
| 200 | 查询成功 | 读取 `items` 渲染列表 |
| 400 | 参数非法（如 `size` 超过上限） | 修正参数后重试，不要原样重试 |
| 404 | 路径不存在 | 检查是否拼错了接口地址 |
| 500 | 服务端异常 | 记录请求 ID，稍后重试 |

## 获取单篇文档

- 请求方法：GET
- 请求路径：`/api/docs/{id}`
- 功能：按编号返回文档正文。

```bash
# 用 curl 验证返回结构（示例地址不可访问，仅示范写法）
curl -s "https://example.com/api/docs/1" | python -m json.tool
```

## 写文档时的一点体会

同一份接口信息，写在聊天记录里只能被一个人看到，写在代码注释里只有改代码的人会翻，写进文档站点则会随每次提交自动发布、有固定地址、能被搜索。把"描述接口"当成产品的一部分，而不是交付后的补丁，是我在这次实践里最直接的收获。
